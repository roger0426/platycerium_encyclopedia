## 4. 功能規劃

### 4.1 前端新增／修改物種 + AI 自動補齊資料

**狀態**：💡　**優先度**：高

#### 目標

讓使用者可以直接在網頁上新增或修改物種，不必手動編輯 CSV。使用者只需要提供部分資料（例如只填學名），其餘欄位由 AI agent 上網搜尋後自動填入，使用者確認後再存檔。

#### 使用流程

1. 使用者點「新增物種」或在物種頁點「編輯」
2. 表單顯示 `plants.csv` 的所有欄位，使用者填入已知的部分（最少只需 `name` 學名，或 `zh` 中文名）
3. 按「AI 補齊」→ 後端 agent 搜尋網頁，填入空白欄位
4. 前端用不同顏色標示 AI 填的欄位，並附上來源連結
5. 使用者逐欄確認、修改後按「儲存」
6. 資料寫回資料來源，頁面更新

#### 決策狀態

- [ ] **AI 呼叫方式**：傾向之後架 server，也評估純前端（TypeScript）直接呼叫 API
  - **方案 A：純前端（TS）**
    - Claude API 支援瀏覽器直接呼叫（CORS），需加上 `anthropic-dangerous-direct-browser-access: true` header
    - web search 是 Claude API 的伺服器端工具，前端呼叫也可以用，不需要自己實作搜尋
    - 限制：API 金鑰會暴露在瀏覽器，只適合 **BYOK（使用者自備金鑰，存在 localStorage）** 或僅限管理者自用
    - 不適合開放一般訪客使用 AI 補齊
  - **方案 B：自架 server**
    - 金鑰放在 server，可以開放給所有人並控管次數與費用
    - 需要維運主機
  - **建議**：先用方案 A 做 MVP（管理者 BYOK），AI 邏輯寫成獨立的 TS 模組，之後要搬到 server 時可以直接重用
  - 改用 TS 需要加入建置流程（建議 Vite），會影響現有「不需建置」的特性
- [ ] **資料存在哪裡**：⏸️ 之後再討論
  - 選項 A：繼續用 CSV，透過 GitHub API commit 回 repo（保有版本紀錄，網站會重新部署；純前端也做得到，用 GitHub token）
  - 選項 B：改用資料庫（如 Supabase / Cloudflare D1），CSV 改成匯出格式
- [ ] **權限**：⏸️ 之後再討論，兩種模式都可能支援
  - 管理者模式：登入後直接修改
  - 公開提交模式：任何人可提交，審核後才上線（類似 PR / 待審清單）
  - 實作時資料流要預留「待審」狀態，避免之後重構
- [x] **照片上傳**：需要支援手動上傳（存放位置隨「資料存在哪裡」一起決定）
- [ ] **AI 費用控管**：每日呼叫次數上限、快取搜尋結果（方案 A 由使用者自己的金鑰負擔）

#### AI Agent 設計草案

- **模型**：Claude API（搭配 web search / web fetch 工具）
- **輸入**：使用者已填的欄位（JSON）+ `plants.csv` 欄位定義 + `regions.csv` 的合法 `key` 清單
- **輸出**：結構化 JSON，每個欄位包含：
  - `value`：填入的值
  - `source`：參考來源網址
  - `confidence`：信心程度（高／中／低）
- **規則**：
  - 使用者已填的欄位不得覆寫
  - `region` 必須是 `regions.csv` 中已存在的 key
  - `parents` 必須是已存在的物種 `id`；若親本不存在，回報給使用者而非自行建立
  - `id` 依學名自動產生（小寫、`-` 連接），檢查不可重複
  - 用繁體中文撰寫描述類欄位，風格參考現有資料
  - 查不到的欄位留空，不要猜
- **可參考的資料來源**：Wikipedia、Plants of the World Online (POWO)、Platycerium 專門網站與論壇

#### 風險與注意事項

- AI 可能產生錯誤資訊（特別是栽培條件、雜交親本），必須由使用者確認後才能存檔
- 網路上的鹿角蕨資料中英混雜、說法不一，需保留來源讓使用者查證
- API 金鑰不可寫死在程式碼或 commit 進 repo；純前端方案只能由使用者在瀏覽器自行輸入

### 4.2 雜交關係圖（Directed Graph）

**狀態**：✅　**優先度**：中

#### 目標

用有向圖呈現品種之間的雜交關係：親本 → 雜交後代，讓使用者一眼看出哪些原生種是常見親本、雜交種從哪裡來。

#### 資料來源

不需要新增欄位，直接由 `plants.csv` 的 `parents` 欄位產生：

- **節點**：每個品種一個節點
- **邊**：`parent → hybrid`（`parents` 中的每個 id 各一條）
- 目前有 6 個雜交種，每個都是 2 個原生種親本；之後可能會有「雜交種 × 雜交種」的多代關係，圖的版面要能處理多層

#### 呈現方式

- **節點樣式**
  - 原生種與雜交種用不同形狀區分
  - 節點顏色使用 `regions.csv` 的地區代表色
  - 可顯示封面縮圖（選做）
- **版面**：D3 力導向圖（d3-force），以彈簧與斥力排版，同時保留分層（親本偏上、後代偏下，依世代用 forceY 拉齊）
  - 起始位置：每個家族（連通分量）放在各自的欄位，避免連線纏繞；孤立原生種漂在下方
  - 懸浮感：模擬保留很低的 alphaTarget，加上依相位錯開的微小漂移力；節點可拖曳，放開後彈回
  - 系統設定「減少動態效果」時關閉漂移與動畫
  - （第一版用 Cytoscape + dagre 的靜態分層版面，改為 D3 以取得彈性、懸浮的互動感）
- **畫面配置**：關係圖在左、圖鑑（列表／品種頁）在右，左右雙開
  - 兩個面板都有 ✕ 可關閉，關掉其中一個時另一個變成全寬獨立介面
  - 頂欄「關係圖／圖鑑」切換鈕可重新打開；只剩一個面板時不能再關
  - 開關狀態存在 localStorage；手機（< 760px）雙開時改為上下排列，關係圖在上
- **互動**
  - 點節點跳到該品種頁面 `#/p/<id>`
  - hover 時高亮該品種的所有祖先與後代
  - 點右側任何卡片（列表、親本、後代）開啟品種頁時，關係圖會平滑平移，把該品種置中
  - hover 節點時跳出懸浮框：封面照片、名稱、學名、地區、尺寸、難度、光照、澆水、溫度範圍（觸控裝置不顯示）
  - 縮放、拖曳
  - 選項：隱藏沒有雜交關係的孤立原生種
- **入口**
  - ~~新路由 `#/graph`~~ → 改為頂欄切換鈕（面板開關不放在網址裡，網址只代表右側內容）
  - 品種頁加一個「在關係圖中查看」連結，開啟後聚焦在該節點

#### 技術選擇

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| **Cytoscape.js + cytoscape-dagre** | 有 CDN、不需建置；分層版面、互動、樣式都內建 | 多一個函式庫依賴 |
| **D3.js（d3-force）**（採用） | 客製化彈性最高，力導向互動有懸浮感 | 程式碼量較大 |
| Mermaid | 寫法最簡單 | 互動能力弱，節點多時難讀 |
